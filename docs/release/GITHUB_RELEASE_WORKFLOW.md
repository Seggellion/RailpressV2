# GitHub source and release workflow

Canonical public source: https://github.com/Seggellion/RailpressV2 . Main receives reviewed source. Pushes trigger the native qualification workflow; they never install customer updates. The separate private Railpress.org repository consumes an exact pin and contains no Rails implementation.

The workflow requires a freshly provisioned, single-job ephemeral native Linux runner labelled `railpress-native-ephemeral`, with the patched toolchain in `/opt/railpress-ci/env.sh`. It has no deployment, signing, provider or private-site credentials. Do not attach a persistent production workstation or run untrusted pull-request code on this runner. Provision/register the runner separately; absence means CI queued/NOT TESTED. The workflow is limited to push main and workflow_dispatch, contents:read, pinned checkout/upload actions, no checkout credential persistence, no service containers and no deploy. Reports contain counts/status only; private state, credentials and raw database artifacts are never uploaded.

Before promoting a version: both native engine jobs, security scan, dependency audit, lint, reproducible production assets/boot, signed-manifest protocol tests and clean-source audit must pass on the exact reviewed commit. Failed, missing or queued checks are a release STOP. Inspect `git status` and package inventories before accepting the candidate. Source-only publication does not waive this promotion gate.

After separate release/signing authorization, tag the exact approved version, build the existing M11 package and manifest from that source, validate its contracts and all assets, and sign via the approved trust authority. Publish a GitHub Release with **manifest.json**, **signature.json**, **package.tar.gz**, **native-plan.json**. The native plan is signed and bound to the release digest using the existing M12 contract. The tag must be vVERSION, published (not draft), with matching prerelease status. Never substitute a GitHub source ZIP for the signed executable package. GitHub API/tag/checksum alone is not publisher authority.

The public client uses the anonymous GitHub Releases API and does not require a token. It fetches bounded metadata, verifies publisher signatures and anti-replay policy, and caches locally. Only a separately provisioned operator fetches packages, verifies bytes/checksum/signatures and performs trusted-UTC, compatibility, backup and host admission. GitHub failure never triggers an upgrade or blocks ordinary publishing. Do not put signing keys in Actions or publish synthetic trust as production trust. M17 deployment, signed distribution and editorial publication remain separately gated.
