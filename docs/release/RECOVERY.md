# Operator-managed fresh-target recovery

The backup unit is private SQL plus an authenticated bounded manifest binding install/core/schema, full table/record/FK evidence, media keys/generations/bytes/SHA256, configuration and retained themes. Preserve original database, secrets and trusted digest separately. A content archive is not a database backup.

Freeze writers/workers/DDL; capture consistent native dump and before/after equality. Provision a distinct empty identified target. Validate manifest checksum, source authority/password continuity, application/schema compatibility, config/key custody and live media. Load once under fixed native deadlines; any error leaves an inactive quarantined one-shot context. No automatic retry/resume over partial DDL.

PG custom archives normally include public schema metadata. The loader preserves the existing correctly owned empty public schema through a narrowly validated restore list; all other SQL errors are fatal in a single transaction. MySQL partial DDL is not atomic. Full post-load schema/FK/enforcement/orphan/record and media checks are mandatory. Revoke staff/Member/reset/preview/OAuth credentials; create new private clock authority and hold scheduling/outbound/queued work pending operator reconciliation.

Only after separate supported-host/provider qualification and maintenance approval: stop original writers, accept data loss since the point, revalidate dependencies, bind the verified new database, restart privately, prove serving identity/public/private/media/health and then reopen. Preserve old database. New writes require a new loss/security decision before returning to old data. No automatic promotion or zero-downtime/RPO/RTO guarantee.

Current executable host admission is synthetic-only. Valuable persistent Disk installations need separately qualified DB+directory recovery. GCS account/project/bucket/KMS catastrophe needs an independent media backup strategy; the initial local contract covers SQL rewind with retained live objects.
