# Fresh-target recovery — isolated alpha candidate

Executable admission currently permits verified synthetic PostgreSQL16/MySQL8.4 profiles only. Production admission/cutover remain unavailable. bin/railpress-recovery accepts backup, validate and restore; it never provisions a DB or migrates an unknown host. Read-only validate never loads SQL, changes objects/IAM/policy or restores soft-deleted media. Checks distinguish VERIFIED, MISSING, MISMATCH, INACCESSIBLE, UNSUPPORTED and UNKNOWN; unverified dependencies cannot yield overall VERIFIED.

Private config format:railpress.fresh-recovery-config.v1 with registry_root,engine,source_profile=gcs_source,target_profile=gcs_good|gcs_bad,root,db_tools,install_id,application_root,configuration_files,theme_root,source_clock_root. Precreate owned/private source/target receipt directories beneath registry .local/state/gcs-recovery. This is separate from the unchanged old NativeHost exact-target snapshot binding. Native tool vectors are explicit; no shell interpolation.

restore also needs manifest path, exact dump and externally trusted manifest SHA256. It acquires a canonical engine/profile lock, refuses an existing one-shot receipt, verifies source identity/installation/password-verifier continuity and unchanged staff, Member and linked-identity authority, distinct empty offline destination without tables/views/routines, capacity, backup and dependencies. It rechecks emptiness, loads once under unchanged native limits, independently verifies complete schema/FKs/records/media, revokes staff/Member/reset/preview/OAuth ephemeral rows, increments auth versions, creates new private clock authority and holds scheduling. Any changed authority refuses; a credential-reset/authority-reconciliation procedure is not qualified here. Queued jobs remain stored but workers/replay are prohibited pending operator reconciliation.

An owned production Rails child checks exact destination/site, credential absence, scheduling hold, content/revision/media relationships and protected Rack routes. With an active theme it checks a media-free published Page without provider access. Actual object reads are independently checked by the validator. This is production Rails/Rack proof, not Chrome/TLS/listener proof. Use an immutable compatible application_root outside candidate private/theme state. No cloud/provider credentials or worker environment enter the child.

Only complete post-load checks yield VERIFIED; native exit0 is insufficient. Failures retain FAILED/QUARANTINED phase receipts and native exit/deadline/cleanup sidecars. Keep the target inactive. No resume over partial MySQL DDL, automatic retry/drop/promotion or original-DB replacement. A new attempt needs separately reviewed scope. Full source schema/record fingerprints are checked after success/failure.

Future separately authorized maintenance cutover: verify host/admission, backup consistency/config/key custody/loss target, stop original writers, recheck password continuity and retained media; accept post-point writes lost; reconcile queued jobs/mail/OAuth and trustworthy UTC; bind the qualified new DB, restart in maintenance, verify actual serving DB/theme/assets/private/public/media health/TLS, then reopen. Record measured outage/RPO/RTO; preserve original DB. Returning after new writes needs a new loss/security decision. No production cutover is executed or qualified here.
