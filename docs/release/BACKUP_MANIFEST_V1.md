# Operator backup manifest v1

railpress.backup.v1 is a private operator recovery record, not M15 content export or restoration proof. Limits:8MiB manifest,256MiB dump,1000media assets/2000objects,4096application/theme files,100000rows/table,64MiB canonical record evidence. Excess limits refuse; no truncation.

Use bin/railpress-recovery backup PRIVATE_CONFIG MANIFEST DUMP only after stopping all writers/workers/DDL under an accepted offline freeze. Admission rejects other DB clients/worker registrations. Capture complete schema/FK enforcement/orphan checks and every table's count/hash, native-dump, then compare full records and persistent dependencies again. offline-before-dump-after-equal-v1 is not a concurrent multi-host snapshot; equality alone never authorizes live writes.

Fields:format/id; engine16.x or8.4.x, sanitized source DB/role/instance/version, dump SHA256/bytes/full schema and record descriptor; application version/schema14/source/schema/migration fingerprints; site UUID; observed creation time/hashed prior clock binding; media bucket/project/key/generation/SHA256/bytes including tombstones; logical configuration hashes; retained theme/package hashes; credential revocation/new clock/stopped-worker/scheduling requirements; unchanged-password-verifier fingerprint; known limitations.

Application inventory covers app/config/db/lib/public/vendor/themes/locked dependencies, excluding compiled public/assets. Retained theme assets are separately hashed. No raw row payload, password hash, session/OAuth token, signing private key, provider secret or private clock authority is included. Schema column names can mention credentials; record evidence contains counts/hashes only. application_secrets is a separate0600 JSON file with SECRET_KEY_BASE for the isolated candidate probe. Optional provider/trust/theme files use logical labels/hashes, never embedded contents. Dumps themselves contain sensitive data and need separately approved private custody/encryption.

Supply the manifest SHA256 through an independently authenticated operator channel. validate/restore require that external trusted digest; a hash in the same untrusted bundle does not authenticate it. No production signing key is used. Strict fields/version/size/private-file checks apply. A correct checksum proves identity, not SQL semantics or restoration: the intentionally invalid native drill dump can match its authenticated hash and still fail native loading.

Wall creation time is audit information, not proof of UTC, security lifetime, backup age, RPO or RTO. No clock authority is reusable. Limitations scope database rewind with retained live GCS, no media catastrophe backup, no automatic cutover/RPO/RTO guarantee, and currently synthetic native-host admission only.
