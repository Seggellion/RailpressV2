# Independent core and site integration

Core is a self-contained CMS, Dusk, protected administration and developer Harness.
A private website consumes an immutable native package and the supported M15
content archive; it does not supply Rails controllers, public tests or host logic.
Use source/package/file digests for uncommitted snapshots; an old Git HEAD alone
does not identify changed source. A deployment pin is not publication permission.

| Boundary | Required qualification |
|---|---|
| Public alone | Fresh source snapshot/package, dependencies/assets/boot, ordinary secure installation and human Harness; no private inputs mounted |
| Private consumer | Independently hashed content and exact core packet/manifest/signature/runtime inventory/theme/API/schema/job/config/clock contracts before extraction |
| Portability | PG→PG, PG→MySQL, MySQL→PG, MySQL→MySQL; compare identities, content/revisions/media checksums/relationships, nonsensitive privacy and theme overlays |
| Accounts | Four installer modes; first local Owner/recovery independent; Members never staff; no provider credentials/accounts in content export |
| Presentation | Dusk light/dark/system and generated art; alternate theme independent; dark protected admin and approved wordmark-free emblem remain core-owned |
| Anonymous privacy | No nonessential anonymous state or automatic provider requests; essential auth/CSRF retained; actual Chrome storage/network review is a separate gate |
| Updates/revert | Only compatible signed synthetic metadata admitted by native clock/key/version/schema/worker gates; a refusal is not a promotion; never SQL-down restore |
| Source/live edits | Three-way conflict inspection, exact-byte idempotency, current fingerprints and explicit review; no destructive automatic synchronization |
| Public contents | Audit source and all Git objects, compiled JS/maps/fonts/images, source/runtime archives and public screenshots; private operational recovery remains private |

Native operations need an admitted host/time/topology; diagnostic installation
does not grant that admission. Real mail/OAuth, trusted UTC, backup/restore, signing
custody, deployment and publicity require separate qualification/authorization.
Unavailable agent/browser workflows remain NOT TESTED. See the current milestone
evidence; historical conditional findings cannot be closed by a later green suite.
