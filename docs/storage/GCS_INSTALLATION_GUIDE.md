# GCS installation on a native Rails host

This is operator guidance, not permission to provision resources or access a bucket. Google Cloud Storage with ADC / Workload Identity is Railpress's recommended production media configuration. Native Linux outside Google Cloud is supported by the configuration interface; actual host/provider admission remains a separate qualification. No Docker, Kamal, GKE or container host is required or qualified here.

1. **Project.** Select an Owner-approved Google Cloud project and billing/custody arrangement. The installer needs the project ID, not a display name, project number, password or API key. Do not reuse production resources for qualification. Project creation and billing changes need separate authorization.
2. **Private bucket.** Select an existing isolated bucket, or have an authorized operator create one. Names are globally allocated; do not put personal information in them. Railpress does not create buckets. Keep public access disabled. [Bucket naming](https://docs.cloud.google.com/storage/docs/buckets).
3. **Region and class.** Choose location for residency, host proximity and recovery requirements. Standard storage is a simple candidate for frequently delivered images; colder classes have different retrieval/minimum-duration implications. This is not an approved region/class choice. Confirm actual prices before committing. [Locations](https://docs.cloud.google.com/storage/docs/locations), [classes](https://docs.cloud.google.com/storage/docs/storage-classes).
4. **Access configuration.** Railpress checks uniform bucket-level access and enforced public-access prevention before object operations. Review organization/project inheritance as well as bucket policy. These controls do not prove every grant is least privilege. [Uniform access](https://docs.cloud.google.com/storage/docs/uniform-bucket-level-access), [public-access prevention](https://docs.cloud.google.com/storage/docs/public-access-prevention).
5. **Least privilege.** Runtime needs `storage.buckets.get` for the adapter's private-bucket metadata check plus `storage.objects.create` and `storage.objects.get` for approved object names. Constrain object access to the approved prefix with a separately reviewed effective IAM policy. Bucket metadata permission has bucket scope; do not assume an object-name condition also grants it. Listing, deletion, overwrite, IAM changes and bucket administration are unnecessary. Do not grant broad Storage Admin. This corrects the earlier R7 proposal's omitted bucket-metadata permission without rewriting that historical proposal. [Permission reference](https://docs.cloud.google.com/storage/docs/access-control/iam-permissions).
6. **ADC discovery.** Railpress calls the maintained Google authentication library and passes the resulting identity to the Storage client. On the pinned native Linux library, discovery checks an explicit `GOOGLE_APPLICATION_CREDENTIALS` file, standard user ADC, a system ADC location, then attached identity. Local inspection checks visibility/type only and never contacts metadata. Point custom configurations explicitly at `GOOGLE_APPLICATION_CREDENTIALS`; changing the gcloud CLI directory alone is not a verified Ruby ADC override. No silent service-account key fallback. [ADC](https://docs.cloud.google.com/docs/authentication/application-default-credentials), [Ruby authentication](https://docs.cloud.google.com/ruby/docs/reference/google-cloud-storage/latest/AUTHENTICATION).
7. **Google compute identity.** On a suitable native Google compute host, an attached service identity can supply ADC without a downloaded key. Have the authorized operator verify the attached identity, API scopes and IAM. Select the attached hint and remove conflicting local ADC files. Railpress's local CONFIGURED result is not metadata/token proof. Managed container platforms are outside this native qualification.
8. **External host federation.** An authorized operator configures a workload identity pool/provider and appropriate principal grants, then provisions the supported external-account ADC configuration and its subject-token source outside source/Git. Select ADC with the federation hint and the explicit configuration path. OIDC/file/URL or supported provider credentials are handled by the maintained library, not browser-supplied endpoints. Executable credential sources are unsupported. Validate the trusted configuration before using it. Pool/provider creation, IAM and external identity-provider access need separate approval. [Workload Identity Federation](https://docs.cloud.google.com/iam/docs/workload-identity-federation).
9. **Why keyless.** Prefer short-lived workload credentials to distributing long-lived private keys. Local developer ADC can use a user account and is useful for development; it does not demonstrate production identity, access or lifecycle readiness. Do not assume ordinary gcloud login configures application ADC. [Cloud Storage authentication](https://docs.cloud.google.com/storage/docs/authentication).
10. **Explicit fallback.** Only when the host requires it, select `service_account_file` on host and installer. The operator provisions a service-account JSON file outside every repository and application release, owned by the app identity, regular/non-symlink, private mode0600 and bounded64KiB. Provide its absolute path through the host environment. Never paste/upload JSON or keys through Railpress, put them in Site settings, exports, Git, logs or backup manifest metadata, or automatically generate a cloud key. Use separate credential custody and revocation. [Key management](https://docs.cloud.google.com/iam/docs/best-practices-for-managing-service-account-keys).
11. **Puma and workers.** Provision durable private bootstrap/theme state and local quarantine outside releases. Give web and workers matching nonsecret backend/project/bucket/prefix/auth settings, compatible credential sources and operator configuration epoch. Apply/restart through the host service manager; the browser never edits these files. Distinct service identities and credential-file layouts require their own host qualification; only the documented local native identity arrangement is tested. For example, these are nonsecret settings, not an executable provisioning script:

    ```text
    RAILPRESS_STORAGE_BACKEND=gcs
    RAILPRESS_GCS_PROJECT=EXAMPLE_PROJECT_ID
    RAILPRESS_GCS_BUCKET=EXAMPLE_EXISTING_PRIVATE_BUCKET
    RAILPRESS_GCS_PREFIX=media/images
    RAILPRESS_GCS_AUTH_METHOD=adc
    RAILPRESS_GCS_ADC_SOURCE=federation
    RAILPRESS_QUARANTINE_ROOT=/var/lib/railpress/private-processing
    RAILPRESS_STORAGE_CONFIG_EPOCH=1
    GOOGLE_APPLICATION_CREDENTIALS=/var/lib/railpress-private/identity.json
    ```

    Uppercase example IDs must be replaced with valid approved values. No example bucket is contacted. Attached identity needs no ADC file setting. Explicit fallback uses its own `RAILPRESS_GCS_CREDENTIALS_FILE` path instead of ADC; remove inactive credential settings. No private key contents belong in this configuration example.
12. **Verification.** In claimed setup, save and verify the nonsecret choice. A mismatch stays pending until operator application/restart. CONFIGURED establishes local visibility/adapter agreement only. After installation, run Site Readiness through the actual queue worker. Real GCS qualification separately requires an approved disposable prefix, identity/private policy, create/read/generation/checksum/denial tests and retained evidence. Read-only metadata cannot prove upload; a file cannot prove tokens. R8 performs synthetic qualification only.
13. **Costs.** Account for stored live/noncurrent/soft-deleted bytes, object operations and network delivery. Retained objects continue costing money. Approve an estimated region-specific budget and workload/byte limits before provider tests. An alert is not a hard spending cap. No price or free-tier entitlement is guaranteed. [Current pricing](https://cloud.google.com/storage/pricing).
14. **Retention and recovery.** Railpress uses create-if-absent, bound generations and canonical SHA256; no public/direct-upload URL. Logical deletion preserves physical objects for accepted backups. Do not remove objects referenced by any retained backup. Inspect actual lifecycle, versioning, retention and soft-delete configuration; none is assumed from the adapter. A deleted/noncurrent copy does not automatically satisfy a live-key read. Restore SQL into a new isolated target, verify every required binding/byte and security epoch, preserve the original and seek separate maintenance cutover approval. Disk recovery is separately unqualified. [Soft delete](https://docs.cloud.google.com/storage/docs/soft-delete), [versioning](https://docs.cloud.google.com/storage/docs/object-versioning).
15. **Errors.** ACTION REQUIRED on setup commonly means missing/unsafe ADC, wrong authentication choice, private-directory permissions or a required restart. Provider MISSING, INACCESSIBLE, MISMATCH and UNKNOWN are distinct failures; do not substitute another key/generation. Effective bucket-get/object permissions, policy inheritance, token scopes and project/bucket mismatch need operator investigation. Never fix an error by making the bucket public, granting broad deletion, disabling TLS or increasing timeouts.
16. **Rotation and response.** Keep credential/subject-token sources private and audit their custody. Revoke compromised grants/keys through a separately authorized operator action, replace the source, advance the nonsecret epoch and restart every affected process. Require a new bounded worker report and provider verification as appropriate. Do not export keys or restore old authority from an ordinary CMS content archive. Preserve incident evidence and follow the security response runbook.

Live provider/IAM/token/retention/production recovery are NOT TESTED until authorized and executed. Selecting GCS is not provider admission, free storage, zero personal data, a GDPR exemption, a website deployment or permission to begin M17.
