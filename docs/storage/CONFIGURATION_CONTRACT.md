# Media configuration and credentials contract — R8

The nonsecret intent format is version1. GCS fields are exactly version/backend/project/bucket/prefix/auth_method/identity_source. Disk fields are version/backend/disk_root. Unknown stored fields are rejected. Project IDs use the supported 6–30-character lowercase ID subset; bucket names obey bounded labels/reserved-name/IP rejection. Prefixes are empty or at most128ASCIIbytes of slash-separated alphanumeric/underscore/hyphen segments, each at most63bytes. URLs, traversal, empty segments and endpoint overrides are unsupported. A pending Disk choice can have an empty operator root; it cannot complete until an actual private directory is configured.

The native product configuration ABI is **2**. Schema14, Theme API1, SecurityClock2 and content archive3 remain unchanged. Configuration1 packages cannot be presented as compatible with a prefixed R8 library. The existing native release manifest/bundle gates enforce this boundary. Same-alpha.1 remains fresh-install development source, not strict-newer update admission; a new source/release pin requires separate authorization. Compatible configuration2 releases must preserve host settings and intent; no automated migration or code-only revert to an incompatible reader is promised.

Host environment is captured at process initialization. The selected adapter remains process-bound; editing a host environment file is not proof of an applied change. Setup saves approved intent privately under the existing bootstrap lock and optimistic revision. Finish rechecks it, stores only the validated nonsecret value in internal PlatformState in the site transaction, then seals installation. Progress survives restart and interruption without storing cloud credentials. Content portability excludes this host state; exports cannot select another backend.

Runtime choices: RAILPRESS_STORAGE_BACKEND=local|gcs; RAILPRESS_STORAGE_ROOT for Disk; RAILPRESS_GCS_PROJECT/BUCKET/PREFIX; RAILPRESS_GCS_AUTH_METHOD=adc|service_account_file; RAILPRESS_GCS_ADC_SOURCE=automatic|attached|federation|native|development; private RAILPRESS_QUARANTINE_ROOT; optional nonsecret RAILPRESS_STORAGE_CONFIG_EPOCH (operator rotation/restart generation). Every process must use the intended settings. A fresh worker report compares configuration, source-locator digest and epoch without storing credential contents. It does not prove principal equivalence. Its SecurityClock2 binding expires; missing/stale/mismatched observations remain visible. The readers deliberately bypass query cache so an earlier empty observation cannot mask a completed worker report.

ADC uses the maintained googleauth discovery API and passes its resulting identity directly to the maintained Storage client. It does not use Storage-specific inline credential aliases. The pinned native Linux lookup order is explicit GOOGLE_APPLICATION_CREDENTIALS, HOME/.config/gcloud/application_default_credentials.json, /etc/google/auth/application_default_credentials.json, then attached identity through Google's metadata detection. Local inspection does not run discovery or contact metadata. CLOUDSDK_CONFIG alone does not redirect this pinned Ruby ADC lookup: use GOOGLE_APPLICATION_CREDENTIALS for a custom location. Inline Google private-key/secret/refresh-token environment alternatives are unsupported. Federation/native/development selections cannot silently fall through when their required file is absent. Service-account key files under ADC are refused: select the explicit fallback instead. An attached selection conflicts with an overriding local ADC file.

Credential files must be regular, owner-private, at most64KiB, without symlink/path indirection, outside application releases and **every Git repository**, including ignored .local directories. Only supported service_account/external_account/authorized_user types are accepted; executable federation sources are unsupported. Fallback requires service_account and delegates to Google's service-account factory. The browser never receives file paths or contents. Only source status is displayed. No credentials, tokens or keys enter Site settings, SQL payloads, forms, exports, logs or backup manifest metadata. Operator files and subject-token sources require their own secure provisioning/rotation/custody.

GCS logical blob keys remain64hexcharacters. Nonempty prefixes map them to prefix/key physical names and are recorded in the immutable binding beside bucket/project/key/generation/byte_size/sha256. Empty-prefix legacy bindings retain their old shape. A binding from another prefix, generation or checksum fails; no unrelated object is substituted. Backup manifests validate and distinguish physical bucket/prefix/key identities. The new reader accepts old empty-prefix manifests; old readers are not qualified for prefixed media. Credentials are never added to media bindings.

Cloud objects remain private, immutable and physically retained. There is no direct upload/public bucket URL, automatic object migration, overwrite, bucket provisioning, physical deletion, policy edit or restore orchestration in this amendment. Effective IAM, live bytes, actual retention and production recovery are independent qualification gates.
