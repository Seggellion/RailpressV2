# Optional private GCS media

The alpha candidate implements a lazy ActiveStorage RailpressGcs service using pinned google-cloud-storage1.62.2. Disk remains the default for development/test and existing installations. Live provider compatibility, effective IAM and bucket policy are separate qualification gates; synthetic SDK/API tests do not qualify a real bucket.

Host-managed production variables: RAILPRESS_STORAGE_BACKEND=gcs, RAILPRESS_GCS_PROJECT, RAILPRESS_GCS_BUCKET, optionally RAILPRESS_GCS_CREDENTIALS_FILE (absolute, owned0600 file outside the distributable checkout) or an explicitly reviewed workload identity/ADC. Never use an inline JSON secret, CMS setting, export field or credential in Git. Provide RAILPRESS_QUARANTINE_ROOT as a private0700 absolute directory outside releases. It holds bounded local processing work, not persistent canonical media. Boot/assets on Disk require no GCS access. GCS client construction is lazy; errors expose bounded status codes, not provider exception text.

The host must enable uniform bucket-level access and enforced public-access prevention. The adapter reads these fields before upload/read and refuses missing/inaccessible/unqualified policy; it never changes policy. The runtime identity needs storage.buckets.get and storage.objects.create/get only. The verifier needs buckets.get/objects.get only. Neither needs delete, overwrite, restore, list, bucket creation, IAM or lifecycle mutation. Inspect effective inherited grants separately: a narrow custom role does not remove broad inherited grants.

The ordinary M04 pipeline validates signatures, bounds processing and normalizes canonical PNG display/thumbnail bytes before storage. Fresh random64hex keys use if_generation_match=0. Blob metadata records bucket/project/key, generation as a decimal string, actual canonical SHA256 and byte size. Downloads look up the live object, compare the binding, download the fetched generation with SDK CRC32C validation and no decompression, then verify actual SHA256/size. CRC32C/MD5/ETag/custom metadata never substitute for canonical SHA256. Keys/generations are not authorization.

No signed object URLs, direct uploads or framework ActiveStorage routes are enabled. Core public-media delivery still requires a currently published public content reference; private/preview delivery retains staff/session/capability checks. Missing, wrong-generation, damaged, denied or unavailable objects return safe missing-media behavior and accessible text. An object stored only as a noncurrent/soft-deleted version cannot pass ordinary live-key verification.

SDK retries are explicitly0, request timeout10s, connection3s/read5s/send5s. These are transport settings, not a verified whole-provider-operation RTO; credential refresh and provider behavior need live qualification. Existing native SQL30s/grace3s/controlIO5s are unchanged. No production bucket/project/credentials are embedded in core. Private Railpress.org configuration remains independently host-owned and unverified.

Before valuable data: separately authorize a disposable real GCS bucket, verify identity, private policy/effective least privilege/no destructive lifecycle, actual create-only upload/generation/download/hash, wrong-generation and denied writes/deletes, outage behavior and retained backup references. Do not provision resources or change IAM/policy merely to run these checks.

Primary references: [official Ruby API](https://docs.cloud.google.com/ruby/docs/reference/google-cloud-storage/latest), [generation preconditions](https://docs.cloud.google.com/storage/docs/request-preconditions), [IAM permissions](https://docs.cloud.google.com/storage/docs/access-control/iam-permissions), [data validation](https://docs.cloud.google.com/storage/docs/data-validation).
