# Native installation and release scope

The application requires the versions in README/Gemfile.lock, a qualified native Linux host, explicit database/storage/private authority, an approved HTTPS origin and correctly configured trusted proxy. Environment keys are RAILPRESS_DB_ADAPTER/HOST/PORT/NAME/USER/PASSWORD, SECRET_KEY_BASE, RAILPRESS_HTTPS_ORIGIN, RAILPRESS_PRIVATE_STATE_ROOT, RAILPRESS_THEME_ROOT and RAILPRESS_STORAGE_ROOT. Store credentials outside Git and release bundles. Remote databases require verified TLS/CA configuration.

Use the interactive operator CLI for setup token, read-only doctor, explicit schema preparation and first local Owner. Do not embed passwords/setup tokens in process arguments, URLs or logs. Dusk installation requires a reviewed trusted package; install keys are not production release-signing keys. Owners retain local/operator recovery when SMTP is unavailable. Optional Member verification supports disabled/email/discord/both, separately from local first Owner bootstrap. SMTP/Discord live-provider configuration and callbacks require their own qualification; synthetic tests are not live proof.

Signed native releases require exact digest/manifest/trust/compatibility, a qualified operator topology, reliable independently established time, process/proxy/worker lifecycle, durable compatible assets and an approved restore plan. SecurityClock2 local fail-closed behavior is tested; independent trustworthy UTC and production release admission remain unqualified. Code revert, theme revert, content revision restore and DB/media/config restoration are distinct operations. MySQL implicit DDL commits require one-shot quarantine on failure. The limited fresh-target local recovery contract is qualified; older populated-resume deadline causes remain unknown and that operation is unsupported. See docs/release/RECOVERY.md. Do not claim SQL-down or a symlink switches live traffic.

Private site inputs can consume supported core APIs and current version3 content archives (legacy version2 input requires a compatible reader). Import is staged private, with explicit reviewed activation, no automatic author accounts or restored credentials. Destination edits and prior-import fingerprints prevent destructive overwrite. Public-source availability does not authorize deploying, signing or publishing an operated website.
